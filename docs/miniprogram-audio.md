# 小程序私有音频与录音（2026-10-15）

## 第四项：鉴权下载后本地播放

采用受控下载，不签发公共播放 URL。`audio/downloads.ts` 仅从资源 ID 和类型构造本项目 API 路径；
`audio/resources.ts` 通过既有 ApiClient/Taro.downloadFile 携带 Bearer 下载，再给播放器本地临时文件租约。
原曲/人声/伴奏、Take、当前会话整体混音共用此入口。Hero 参考匿名只读；所有 Take/混音和非 Hero 参考需要可信身份。
Token 不出现在 URL、播放器 src、任务记录或日志中，也不采信 Profile 提供的任意外链。

每次 acquire 都明确持有临时文件，完成后调用 release；不建立跨会话磁盘缓存或公开文件目录。
退出/换号使下载代次失效，取消未完成下载、清理迟到文件、撤销已有租约；账号不符/凭证到期不能读取租约路径。
租约到期自动释放，并通知播放器停止；同一账号续期不会给旧租约延长无限离线缓存。
已经授权下载到客户端的字节不能由服务器远程收回，此方案依赖小程序沙箱及本地生命周期清理，不声称 DRM。

后端 Take/混音及私有参考音频响应添加 no-store、Vary Authorization/Cookie 和 nosniff；
原有 Range 支持保留，所有 Range 请求仍先验证所有者。查询参数里的 Token 不能授权，无 `/data/` 静态绕过。
混音仅复用当前服务端成品下载能力，不代表第七项预览缓存/重新生成与多轨 UI 已完成。

本项回归：客户端音频资源 4 项、后端私有下载/微信鉴权相关 26 项、类型检查与 Ruff 通过。
本轮构建在 Taro 初始化阶段长时间无编译进展，已按用户要求中止；将在后续录音/播放最终构建统一复验，不宣称本次独立构建通过。
真实微信下载、播放器权限与退出清理尚待设备和独立 HTTPS 入口验证。

## 第五项：微信录音生命周期

`recording/controller.ts` 稳定持有 RecorderManager 适配器，不随页面组件卸载重建。
按“隐私/麦克风授权 → 伴奏完整下载与 canplay → 3 秒倒计时 → start 请求 → 原生 onStart → 参考播放”推进，
只有正常请求停止且收到有效 onStop 文件后进入试听。拒绝权限、准备失败、后台/锁屏/系统暂停中断、退出或换号不进入成功状态。
开始/停止事件、大小/时长和冻结的选择范围随本机 clip 保存；原生采用 16 kHz、64 kbps、单声道 MP3，真实容器仍由后端识别。
格式参数依据安装的 Taro RecorderManager 类型；未宣称在真实 iOS/Android 验证。

`privacy.tsx` 使用微信隐私授权事件和 agreePrivacyAuthorization 按钮，不自动代替用户同意。
需要在公众平台填写与实际 Gemini 处理用途、供应商和区域一致的隐私指引；本轮未配置平台声明，未伪造备案/授权。
麦克风拒绝后提供用户主动打开设置的入口。正式隐私条款/素材授权仍属于第十一项发布前核验。

首页提供三首既有 Hero 的远程入口，练习页可选主/次声部与连续句范围，录音服务在页面内保持稳定。
`PracticeWorkflow` 使用短请求和前后台串行轮询；保存和仅分析都刷新 Memory，后者在终态删除 Take 音频但保留 Attempt。
清理失败不会显示完成，按 origin/owner 持久化 Take ID、模式与清理阶段，重新登录可继续清理；不保存 Token 或音频路径。
网络未确认上传时不自动重发；无法获知服务器是否已收件的极端中断仍需后续保留期清理策略，不承诺崩溃瞬间绝无孤儿文件。
中文歌曲只保存录音，不发起 Gemini 练唱分析。已保存录音可受控试听和删除，Memory 页面读取当前可信用户统计。

录音/提交语义测试 6 项、类型检查和生产构建通过；首次真正导入 shared 代码时发现 Taro 默认未编译根目录 TypeScript，
已用 mini.compile.include 明确纳入共享层。也将 Array.at 改为兼容索引访问；逻辑语义不变。
构建脚本现在在 4 分钟后停止整个构建进程树并返回未通过状态，避免初始化停滞时空等。
来电、耳机切换、系统录音回调顺序和隐私组件仍需真实设备验收，系统未发出事件的硬件切换不能仅靠单元测试证明检测可靠。

## 第六项：参考播放与同步证据

`LocalPlayer` 只创建一个 InnerAudioContext，参考、录音伴奏、本机试听与已保存 Take 互斥。
原曲/人声/伴奏受控下载后播放；canplay 门禁、seeked 确认、加载/跳转超时均有明确错误。
支持原速与 0.75×，若原生属性不接受速度则提示原速；API 接受属性不代表所有设备均已实测。
所选句范围按真实 currentTime、timeUpdate 与计时器循环/暂停，文件结束也处理循环；不是共享时钟多轨或采样级循环。
整句歌词按实际秒位置高亮。改选范围会重置参考，歌词点击可跳转；主次歌词不互相冒充。

录音预先确认伴奏起点，onStart 后请求播放，收到真实 onPlay 后才计选区时长；3 秒没有播放事件则中断。
等待、暂停、跳转、错误等参考异常中断录音；后台/卸载/退出使原生播放停止，迟到下载不能复活旧播放器。
录音伴奏固定 1×，不使用预览的循环和变速参数。原生回调无法证明实际扬声器声学起点，仍需真实设备校准。

Take 上传新增可选 `sync_evidence` JSON，响应为 `syncEvidence`，SQLite 通过既有 Take JSON 持久化，无新增音频副本。
`wechat-sync-v1` 使用 `client_wall_ms`：atMs 相对录音启动请求的客户端毫秒，positionSeconds 为参考歌曲秒位置。
成功顺序为启动请求、录音开始、参考播放请求、参考实际播放、停止请求、录音停止；最多 16 KiB，字段/顺序/有限值校验，错误不回显原始 JSON。
observedStartGapMs 仅记录参考实际播放与录音开始回调之差，不自动写成设备声学延迟。
calibratedDeviceLatencyMs 与已有 latencyCompensationMs 一致；默认 0/unverified，用户手动填写后标为 user_calibrated。
正补偿使 Take 在伴奏时间轴提前（timelineStart − latency/1000 + manualOffset/1000）；符号沿用共享时间轴测试。
证据属于用户自报观察，不能用作鉴权、可信测量或替代 iOS/Android 真机校准。旧 Web 未上传此字段时保留 None。

最终验证：客户端登录 9、网络 16、共享 3、音频 8、录音/提交 8，共 44 项；后端 168 项、Ruff、类型检查、构建和包检查通过。
后端排除缺少 Hero Profile 的两个历史资源测试文件（10 项），未复制旧项目素材或重跑模型 Pipeline；Web 依赖未装，未跑 Web 回归。
真机需要验证：权限拒绝后重试、MP3 实际容器、隐私同意、后台/来电/耳机、弱网、0.75×、循环误差、两系统延迟和跨用户下载撤销。
当前没有独立部署入口/合法域名及后端微信凭证，以上为本地模拟回归与构建结果，不能标为正式发布验收。
