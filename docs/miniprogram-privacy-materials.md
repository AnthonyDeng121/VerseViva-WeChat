## 实际数据流与本轮修改

| 环节 | 实际处理 | 本轮结果与边界 |
| --- | --- | --- |
| 微信登录 | code 交给服务端换码，存 AppID 范围 openid 摘要与随机 owner；Token 存摘要 | 沿用可信身份，不把客户端用户自报 ID 当授权；没有索取或打印真实密钥 |
| 本机录音 | 隐私授权与麦克风授权先于 RecorderManager；产生本地临时文件 | 沿用已有授权调用；平台隐私指引配置和真机授权仍未验 |
| 保存/分析上传 | 原录音写入独立服务端 Take，保存模式决定后续处理 | “仅分析”同样临时上传，靠分析流程后显式删除，不是从不落盘；崩溃/弱网可能需要清理重试 |
| Gemini 音频分析 | 参考人声、用户录音裁片及歌词/目标发给 Google Gemini API | 三处 Interactions 调用显式 `store=False`；Files 删除仍尽力执行，失败只记录固定安全日志，不记录 URL、文件 ID、路径或异常原文 |
| 可选 GLM 文字建议 | 配置 GLM Key 后，问题和历史趋势发往配置的兼容端点 | 移除 owner/session ID、精确练习时间、hint/sentence ID；保留随机问题 ID 用于映射建议，以及必要事实和趋势；不发原始音频。不能据此声称完全匿名，事实/歌词可能仍含用户信息 |
| 保存后删除 | 现有删除 Take 同时清理默认反馈并使混音失效 | 新增持久化删除标记，迟到结果不能重新写回 Memory；歌曲删除也覆盖相关 Take 的迟到反馈 |
| 仅分析后的 Memory | 删除音频时 `preserve_attempt=true` 保留结构化反馈/历史 | 新增鉴权 `DELETE /api/v1/practice/attempts/{attemptId}`，删除已无 Take 的保留反馈，返回 204；跨用户/不存在返回 404；尚有 Take 返回 409，使用原 Take 删除入口。该接口尚未接到界面，不声称用户已有新的按钮 |
| 备份/第三方数据 | 备份可能含删除前数据；第三方有自身条款和日志 | 用户删除在线数据不等于所有备份或供应商日志立刻抹除，也不保证安全擦除 SQLite/WAL 的历史物理字节 |

`GET /api/v1/privacy/facts` 返回版本化、no-store 的技术事实及 AI 生成属性，不回显 Key、端点 URL、所有者身份、文件路径或原始 JSON 输出。它不是正式隐私合同，也不会自动显示给用户或替代显式同意。服务端仍不能把微信登录、麦克风授权或请求此接口视为用户已同意第三方处理。

默认删 Take 不保留反馈；仅分析主动保留的反馈可由新接口单独删除。删除标记只存 Take ID，用于阻止迟到回写，不是声学数据或重新可见的练习历史。没有新增注销账号、全账户擦除、自动删除备份或远程撤回已下载文件能力。

## 供应商事实核对

本轮阅读了官方资料，不能据代码或服务器所在地自行确定实际处理区域：

- [Gemini Interactions 数据存储](https://ai.google.dev/gemini-api/docs/interactions-overview#data-storage-and-retention)：默认保存交互，`store=false` 可关闭此类持久状态；本项目分析不依赖多轮状态或供应商后台任务，所以显式关闭，不影响本地后台任务方案。
- [Gemini Files](https://ai.google.dev/gemini-api/docs/files)：可主动删除上传文件，文档也列出 Files 自动保留期限；不能将该文件期限扩大解释为所有服务日志或审查数据都在同一时刻删除。
- [Gemini 服务条款](https://ai.google.dev/gemini-api/terms)：付费/免费服务的数据使用规则不同；免费服务涉及改进产品与人工审阅，付费服务也有安全日志及处理地点条款。当前项目实际计费账户、数据处理约定和日志设置尚未核验，不能承诺“不训练”“完全境内”或“即时彻底删除”。条款还对适用地区和受众有要求，须核对实际账号与发布人群。
- [可用地区](https://ai.google.dev/gemini-api/docs/available-regions)：本轮页面中未找到 China。新加坡服务端能够请求成功，不等于向中国大陆用户提供服务已获得条款许可；发布前需要确认适用服务方案，不能仅靠出口网络绕过该问题。当前没有替换模型；如需替换，必须另验音频、结构化输出与反馈质量。
- [微信隐私授权文档入口](https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/PrivacyAuthorize.html)：本轮工具未能读取该页正文，不能声称已完整核验最新平台规则；已有代码使用 requirePrivacyAuthorize、onNeedPrivacyAuthorization 和 agreePrivacyAuthorization，仍需按公众平台实际要求配置并在真机验证。

GLM 端点可配置，不能只凭默认域名推断真实供应商、合同主体或处理地点。当前未对实际配置做网络请求；若启用，需额外核验供应商、区域、保留政策与用途说明。

## 素材与发布证据

`deploy/wechat-release-review.json` 记录三个现有公共 Hero ID，均为 `unverified`，不伪造授权文件或把缓存当许可证。授权范围分别记录 `audio_distribution`（音频公开提供）、`lyrics_display`（歌词展示）、`derived_audio`（人声/伴奏等衍生产物）、`model_processing`（发送模型处理）。需要由实际权利证据支持，或经用户确认更换为自制/有授权素材；本轮不静默删歌、换歌或改变界面。

该清单还记录隐私合同、录音授权、AI 提示、区域、供应商条款/受众、删除与备份、微信平台配置。`reviewed`/`authorized` 是维护者记录，不是工具签发的法律认证；证据应指向实际批准文件/记录，不能只把 pending 改成 reviewed。没有读取私人授权文档，也没有向版权方发消息。

```text
python -m server.release_audit --review deploy/wechat-release-review.json
python -m server.release_audit --review <实际核验清单.json> --glm-enabled
```

当前清单会输出缺项并返回退出码 1，这是预期结果。脚本检查所有固定 Hero 的用途记录、审核证据非空和供应商区域状态，拒绝重复 ID、缺失/非法清单；它不联网验证授权真实性、授权到期、文件替换后的内容一致性，也不检查微信控制台是否已配置。

新增 `VERSEVIVA_RELEASE_REVIEW_REQUIRED`（默认 false，保留当前本地/Web 行为）、`VERSEVIVA_RELEASE_REVIEW_FILE`（默认 deploy 下样例路径）。独立微信 `.env.wechat.example` 开启检查，路径 `/app/data/wechat-release-review.json`；实际部署需将完成核验的清单放入独立数据卷。镜像不自动把样例清单当成审批证据，缺失/未核验时启动前拒绝，且不创建任务或调用模型。本轮没有启用本地环境、启动容器或部署。

## 不改界面留下的明确欠项

1. 现有“仅分析不保留云端录音”容易被理解成无临时上传/无第三方保留；“后端 Gemini 服务”未覆盖可选 GLM，保存但不分析也会上传。需要用户最后测试时明确同意后，再改相关说明。
2. 正式隐私指引必须填写真实运营者、联系方式、目的/数据类型、供应商和区域、保存/删除与备份处理；本轮只提供上述技术底稿，不填造运营主体、备案或实际存储国家。
3. AI 生成属性已在技术事实中明确，但没有新增用户可见标识。实际展示方式与是否需要单独同意/标识仍待平台要求和实际发布方案核对，不将后台字段当作界面已展示证明。
4. 保留反馈的独立删除目前只有鉴权 API；UI 接入、账号注销/全量删除及公开保留期尚未完成，不能宣称用户端隐私闭环已验收。
5. 三首 Hero 授权、替换素材、供应商地区/受众/计费条款、正式平台配置与真机验收仍是发布前欠项；当前不是可直接正式上线的证明。

验证：新增 25 项隐私/素材测试，加上更新后的 36 项可靠性测试，定向 61 项通过；后端 272 项通过（继续排除既有两个缺 Hero Profile 的测试文件，共 10 项未验）。Ruff、差异检查与前端零变更核对通过；样例清单检查按预期失败。测试使用模拟供应商与临时数据，未调用外部模型/运行 Hero Pipeline，未跑客户端构建或真机。新增 store 参数虽经官方文档和模拟契约核验，仍待实际部署模型调用验证。
