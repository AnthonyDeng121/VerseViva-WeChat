# 小程序移动端歌词与反馈（第八项）

> 2026-10-15 用户要求恢复原 H5 布局：下文垂直卡片、内联符号与逐句列表方案已被撤销。当前未提交恢复工作改为普通/左右双轨歌词切换、原下置标记、单个详情及反馈翻页，状态见 [布局恢复记录](miniprogram-layout-restore.md)。本页原构建数字不代表当前工作树。

目标是让窄屏下的歌词、语言标记和 AI 反馈保留可读性与证据边界。此前只有当前 lane 的纯歌词、辅助读音和建议列表；现在同句主唱/次声部以垂直卡片显示，分别标注当前练习声部、来源和复核状态，并提供语言点详情与逐句历史比较。

## 实现入口

- `miniprogram/src/lyrics/presentation.ts`：纯字符投影、来源/置信度/比较文案和逐句建议关联。
- `Lyrics.tsx`：歌词、标记点击、详情、声部元数据；`SongPractice.tsx` 保留范围、声部选择、音频跳转和录音入口。
- `Feedback.tsx`：根据 Attempt 自身 lane、sentenceIds、issues 和 sentenceComparisons 展示本次录音反馈；恢复任务入口也可显示反馈，无歌曲 Profile 时只用句序，不自行猜测歌词。
- Memory 页面：现象累计/近期次数、服务端趋势；不自行改变聚合算法。

## 字符与证据边界

索引使用 Unicode code point，与后端 Python 字符索引一致。删除括号和另一声部文本时保留原字符到显示字符的映射；标记的完整起止范围必须仍处于同一声部。目标词索引同样检查所在 lane。禁止通过重复词的贪心匹配把另一声部的标记接过来。

次声部只投影该 lane 内唯一精确出现的 Vocal Part 文本；重复出现或不能匹配时保留声部原文，隐藏无法确认的标记。日韩辅助读音有独立索引，标记只绘制在罗马音行；原文包含双声部但罗马音缺少边界时不推断对应关系。句子显示“部分语言标记尚不能可靠定位”提示复核。后续可通过明确的声部罗马音和字符映射扩展，不应直接复制原文字偏移。

三种符号以可换行内联文本和详情按钮呈现，保留完整 `└─┘` 符号；没有复刻浏览器按像素拉伸的跨词桥线。详情显示实际映射目标、原文、读音、动作、解释、来源、置信度、证据强度和复核状态，不把置信度当作演唱分数。ASR 歌词警告仍在歌词卡上方。未向 UI 输出原始响应 JSON 或内部降级方案名。

反馈建议只关联本句 issueId。只有 analyzed 才展示逐句建议，failed 与 insufficient_data 分别显示服务不可用/证据不足，不产生演唱诊断、不计趋势。比较直接读取服务端逐句同目标结果，缺失比较时不冒充首次可靠记录；不会用问题总数下降推断改善。Memory 是既有聚合结果，最近窗口最多 5 次可靠尝试，某现象的聚合趋势不能证明其中所有目标改善。
