## 1. 验收顺序和准备边界

按“本地证据 → 独立环境准备 → 真机正常闭环 → 异常/隔离 → 测量 → 缺陷复验”推进。当前只完成文档准备；实际部署必须另获用户明确授权。以下环境准备是后续操作说明，不代表已执行。

| 顺序 | 准备与核对 | 完成依据 |
| --- | --- | --- |
| P1 | 固定待验 Git commit、客户端构建、服务端版本；保留 urlCheck=true；导入 miniprogram/，源 miniprogramRoot=dist/ | 记录 commit、构建时间、包检查与原生 WXSS 编译结果；构建成功不能代替微信运行 |
| P2 | 用户确定微信版独立 HTTPS 域名、服务器、数据卷与端口；沿用 compose.wechat.yaml 单 worker | 核对独立命名卷、证书和最终 API 域名；不连接原 Web 生产服务或共用其可写卷 |

## 2. 正常闭环（iOS、Android 分别执行）

每次先登录测试账号，使用同一待验版本；每条记录操作时间、期望与实际、脱敏证据编号。按 ID 执行，关键前置失败时停止相关后续步骤，保留现场以定位。

| ID | 操作 | 通过条件 |
| --- | --- | --- |
| N01 | 冷启动 → 微信登录 → 退出 → 重新登录同账号；重新打开小程序 | 真实 code2Session 成功；同账号数据归属稳定；退出后不能继续私有操作，旧请求不回写 |
| N02 | 选授权歌曲与句范围，分别查看主/次声部、日韩罗马音标记、ASR 来源与反馈详情 | 不跨 lane 关联目标；来源/复核信息符合 Profile；视觉与原交互仅记录差异，未经要求不改 |
| N03 | 原曲/人声/伴奏播放、句跳转、循环、0.75×；启动录音前参考预加载和倒计时 | 播放互斥、句高亮匹配所选范围；录音用原速，实际参考未播放或起点不符时不能假成功 |
| N04 | 录制短片段 → 停止 → 本地试听 → 分析并保存 → 等待 Attempt 终态 | 实际 MP3/临时文件可上传并解码；仅一次显式提交；Take 可查/播放，可靠反馈与 Memory 刷新。记录上传、排队、分析耗时 |
| N05 | 同目标再练一遍，另录次声部；查看逐句比较与 Memory | 比较来自同句同 lane 的可靠历史；failed/insufficient_data 不生成改善结论、不计入可靠趋势 |
| N06 | 录音 → 仅分析 → 等待完成并回到列表/Memory | 临时 Take/音频清理完成，结构化 Attempt/Memory 保留；不是“从不上传”。清理失败需可恢复，不能假报完成 |
| N07 | 中文歌曲使用纯唱/只保存，试听已保存 Take | 不触发语言诊断；播放、保存与后续混音可用 |
| N08 | 两条 Take 分别调整 gain/mute/偏移，选择范围和伴奏/人声/整体增益，生成混音、下载试听 | 单个成品播放；静音/音量生效，空隙伴奏连续，播放位置映射歌曲时间；参数变化停止旧成品并重新生成 |
| N09 | 删除已保存 Take，再访问其音频、反馈与旧混音；另用私有测试歌曲验证整歌删除 | 默认 Take 删除清理反馈并失效混音；私有歌曲删除清理其派生资源；旧下载不可重新获取。运行中成品完成后丢弃；不删除公共 Hero |

N09 的服务端文件清理需在获授权的独立测试环境由操作者检查；听不到或接口拒绝下载本身不能证明磁盘文件已删除。N06 保留反馈的独立删除只有 API，使用下节 A08 验证，不能要求尚不存在的按钮。

## 3. 异常、恢复与跨用户用例

故障注入只针对用户授权的独立测试环境与自有测试数据。设备设置/系统行为可直接测试；缩短 Token TTL、撤销 Token、中断服务或模拟供应商失败属于后续受控环境操作，不在原生产服务上执行。网络恢复后先查询结果，再决定是否显式重试写操作。

| ID | 操作 | 通过条件与证据 |
| --- | --- | --- |
| A01 | 首次拒绝隐私/麦克风授权，之后在微信设置允许再重录 | 拒绝时不录音/上传，不产生成功状态；允许后可恢复。分别记录隐私与麦克风授权 |
| A02 | 分别在倒计时、录音期间切后台/锁屏/接听来电/插拔或切换耳机，再回前台 | 中断不伪装完整成功，不自动上传；可重新录制；记录系统实际触发的事件，无法触发者保留未验 |
| A03 | 下载、上传、任务查询期间分别断网/切网/限速，再恢复 | 下载失败可显式恢复；POST/上传不自动重发。查询串行、有限退避；结果未知时不假定失败或重复创建 |
| A04 | 分析/混音进行中隐藏页面、返回、关闭并重开小程序 | 隐藏暂停查询，返回查最新状态；任务按 origin/owner/song 恢复；后台完成不自动播放；迟到结果不污染新页面 |
| A05 | 在测试会话到期后并发请求；再验证退出期间仍有下载/查询未完成 | 单次 401 重放、并发续期去重；退出清理租约，旧响应不回写。用测试端观测次数；不记录 code、Token、openid 或完整授权头 |
| A06 | A 创建私有 Song/Job/Take/Attempt/混音；B 用这些资源 ID 尝试查询、下载、改动与删除，再回 A 核对 | B 被拒绝且读不到 A 内容，A 原数据未变；Memory 各自隔离。公共 Hero 可只读不是越权。不能只测列表未显示 |
| A07 | 用静音片段、证据不足录音；在受控测试环境验证模型超时/失败和任务重启中断 | 静音门禁不调用模型；供应商故障为 failed、证据不足为 insufficient_data；不伪造成功/改善。重启中断有真实终态与显式重试 |
| A08 | 用 A 的 N06 保留反馈，经鉴权 API 删除；B 越权删除；另对仍有 Take 的 Attempt 调用删除 | DELETE /api/v1/practice/attempts/{id}：A 删除无 Take 反馈返回 204；越权/不存在 404；仍有 Take 返回 409。确认历史/Memory 更新，迟到结果不重新写回；无新增 UI |
| A09 | 在独立测试配置下验证预算耗尽、超时长/超大小/无效音频与空间门禁 | 分别核对 429/413/415/507 及无残留本次文件；不对生产盘填满，不用海量模型请求耗尽预算；纯本地回归证据与实际环境验证分开记录 |

跨用户 API 检查需在受控测试客户端临时持有各自 Token，只记录 HTTP 状态与脱敏结果，不把凭证填入验收表。账号切换后另核对本机临时音频、任务恢复索引不会向 B 展示 A 的内容。

## 4. 延迟、循环与混音偏移测量

使用自制且具有清楚瞬态的短参考片段和已知相同录音设置，每个系统/设备/耳机路径分别至少测三次。记录原始值、测量方法与误差范围，不把某一次结果推广到所有设备。

1. 记录参考实际 onPlay、录音 onStart 与 syncEvidence（相对毫秒/参考位置秒）。它们只反映客户端观察，二者回调间隔不是声学设备延迟。
2. 用可重复的声学/波形对齐方法比较同一参考瞬态与录音；记录拾音方式、人工反应和测量误差。无法区分演唱反应与设备延迟时只报告“观察偏差”，不填写“设备已校准”。
3. 使用已知瞬态的测试 Take，对比补偿/手动偏移 0、+200、-200 ms 的混音。时间为 timelineStart − (latency + manualOffset)/1000，正值提前；确认方向及实测偏移，同时验证静音/增益与连续伴奏。
4. 选定句范围循环至少三轮，记录边界实际偏差、跳转后首个位置及是否漏播/重播；0.75× 单独记录支持与失败表现。原生位置采样与人工听感均不能宣称采样级精度。
5. 先记录数据，再由用户确定可接受阈值；阈值未定的量化项标记“待判定”，不自行宣布体验验收通过。

## 5. 回归选择与完成判定

本轮仅文档变动，核对链接、命令入口与 git diff --check 即可；前次 276/70 项仍标注为历史证据。后续按变动范围选择测试：鉴权/删除/任务逻辑跑对应后端测试，客户端逻辑跑相关 node 测试和类型检查；客户端或构建配置变化再构建、检查包及原生 WXSS。命令与已知缺资源的 10 项见交接记录。Web 改动才补其 test/lint/build，当前 Web 依赖未安装，不写成已通过。

用例“通过”必须同时有实际结果、版本与证据；“失败”保留缺陷编号，修复后记录新版本复验；“阻塞/未执行/待判定”不计通过。两系统正常闭环、异常与隔离、测量结果以及发布欠项分开评估。第十二项本地准备完成不等于真机验收或正式上线完成。
